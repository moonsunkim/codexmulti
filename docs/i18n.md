# UI translations

CodexMulti owns its UI copy in the Zig core. The Swift shell reads projected text over
`cm.bridge/1` and static menu/dialog text through `cm_copy_text`; it does not maintain a
second translation catalog. Provider names, account labels, paths, protocol identifiers,
and unrecognized provider diagnostics retain their original values.

| Selection | Persisted/bridge tag | Catalog | C copy ID |
| --- | --- | --- | --- |
| System | `system` | Resolved by the Swift shell | Uses the resolved language |
| English | `en` | `core/src/strings.zig` | 0 |
| 한국어 | `ko` | `core/src/strings.zig` | 1 |
| 日本語 | `ja` | `core/src/strings_ja.zig` | 2 |
| 简体中文 | `zh-Hans` | `core/src/strings_zh_hans.zig` | 3 |
| Español | `es` | `core/src/strings_es.zig` | 4 |

Explicit selections persist in app settings and take effect without restarting. System
uses the first macOS preferred language. Identifiers are case-insensitive, and `_` and
`-` separators are accepted. Korean, Japanese and Spanish accept regional variants.
Chinese with an explicit `Hans` script, bare `zh`, or the `CN`/`SG` region selects
Simplified Chinese. Explicit `Hant` takes precedence over a region; Traditional Chinese
and other unsupported preferences fall back to English. An explicit app selection
always overrides system detection.

The Spanish catalog uses shared vocabulary for Spain and Latin America. Dates put the
day before the month; Chinese dates use year/month/day. Durations and account counts
are formatted in the selected language. Abbreviated units avoid incorrect singulars
in compact Spanish duration labels.

## Updating copy

1. Add static keys to `StaticKey`, or formatted keys to `FormatKey` and `FormatArgs`, in
   `core/src/strings.zig`. Supply every catalog entry. Missing entries fail compilation.
2. Preserve all arguments in format strings. Use Zig positional arguments when a
   translation changes their order, such as Spanish dates. Keep spaces in dialog
   prefixes/suffixes and summary separators; those pieces are joined at runtime.
3. Keep language names in their own language in every catalog. When adding a language,
   extend `Language`, `catalog_languages`, the catalog dispatch, the C copy ID mapping,
   the core settings projection and Swift decoding, picker, copy mapping and resolver.
   Existing persisted tags and C copy IDs must keep their meanings.
4. Add new catalog files to `core/scripts/core-source-list.txt` so bundle provenance
   includes them. Update language links and support statements in every top-level README.
5. Regenerate and synchronize the bridge fixtures when their supported language list or
   settings fields change. This is an additive change within `cm.bridge/1`; Swift's new
   language-label fields are optional to keep older projection fixtures readable.

## Verification

With Zig 0.16.0 on `PATH`, run:

```sh
(cd core && zig fmt --check build.zig src)
(cd core && zig build test && zig build test-bridge)
(cd core && zig build export-fixtures)
./app/scripts/sync-fixtures.sh --sync
./app/scripts/build-app.sh
(cd app && CODEXMULTI_TEST_HEADLESS=1 swift test)
```

The core tests cover catalog completeness, UTF-8, formatting, localized projections and
saved language preferences. Swift tests cover regional language detection, bridge
encoding/decoding and immediate shell-copy changes. Use the headless environment flag:
plain `swift test` opens windows.

For visual review, export a synthetic localized projection, then render it with the
staging executable's `--fixture`, `--capture`, `--no-activate` and `--no-status-item`
options. The fixture exporter supports `--korean`, `--japanese`, `--chinese` and
`--spanish`, followed by a fixture name and output path. Review both the account details
and Settings, including long labels and confirmation text. No provider access is needed.

The English README is the source for translated README content. Translate visible prose
and image descriptions while preserving commands, paths, links and operational conditions.
Shared screenshots currently show the English UI and use synthetic accounts.
